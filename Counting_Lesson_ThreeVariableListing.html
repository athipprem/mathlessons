🪙 Two Coins Was Easy. Three Coins Got Messy.

Why learn this?

You already know how to list coin ways with TWO coin values — sweep the bigger coin down from its max, and the smaller coin fills the rest. But on the last test, a question used THREE coin values (1¢, 2¢, 5¢) at once, and the list fell apart — too many things to hold in your head at the same time. The fix isn't a new idea, it's an ORGANISED table: one column per coin, and you sweep one variable at a time, just like you always have — just twice instead of once.

Three things to track is not harder maths — it just needs a bigger table and a calmer sweep.

The Big Idea — One Column Per Coin, Sweep the Biggest First

With 2 coins, you swept ONE variable (the bigger coin) and the smaller coin was decided automatically. With 3 coins, you sweep the BIGGEST coin first — and for every value you pick, you get a smaller, familiar 2-coin problem left over.

Fix the biggest coin's count → solve the leftover with the OTHER two coins (a job you already know) → move to the next biggest-coin count → repeat.

⚠️ NEVER free-list all three at once from memory. Always build a table with one column per coin, block by block. The block-by-block table is what stops rows from getting missed or repeated.

Worked Example, Part 1 — Pay 6 Cents

How many different ways can you pay 6 cents using only 1-cent, 2-cent, and 5-cent coins?

Step 1 — sweep the BIGGEST coin (5¢) from its max down to 0. Max 5¢ coins here = 1 (since 2×5=10 > 6).
Block: 5¢ coins = 0 → leftover = 6. Now it's a familiar 2-coin job (1¢ and 2¢):
2¢ coins = 0,1,2,3  →  1¢ coins = 6,4,2,0  →  4 rows
Block: 5¢ coins = 1 → leftover = 6−5 = 1. 2-coin job again:
2¢ coins = 0  →  1¢ coins = 1  →  1 row
Step 2 — add up EVERY block's rows, not just the last block:
4 + 1 = 5
5 ways

Worked Example, Part 2 — A Bigger Target, More Blocks

How many different ways can you pay 17 cents using only 1-cent, 2-cent, and 5-cent coins?

Same method — just more blocks, because 5¢ coins can now be 0, 1, 2, or 3.

5¢=0 → leftover=17 → 2¢=0..8 → 9 rows
5¢=1 → leftover=12 → 2¢=0..6 → 7 rows
5¢=2 → leftover=7 → 2¢=0..3 → 4 rows
5¢=3 → leftover=2 → 2¢=0..1 → 2 rows
Add up EVERY block:
9 + 7 + 4 + 2 = 22
22 ways
More blocks just means more ADDING at the end — the method inside each block never changes.

🗺️ The Plan

1Find the biggest value's maximum (how many of the biggest coin/item could possibly fit).
2Build a table with one column for every value, plus a Row Total column.
3Sweep the biggest value from 0 up to its max, one block at a time. For each block, solve the leftover using the other two values — the familiar 2-variable method.
4Write down each block's row-count before moving to the next block — don't just remember it in your head.
5Add up ALL the blocks' row-counts at the end — that total is your answer, never just the last block's count.

⚠️ The listing rule from before still applies: the answer is the COUNT of rows, never the last row's numbers.

P4.  How many different ways can you pay 10 cents using only 2-cent, 3-cent, and 5-cent coins?
5¢=0 → leftover=10 → 2¢+3¢=10: (5,0)(2,2) → 2 rows.

5¢=2 → leftover=0 → (0,0) → 1 row.
2 + 1 + 1 = 4.

📖 Listing With Three Things — in one line

Sweep the biggest value block by block. Solve each leftover with a familiar 2-variable table. Add up EVERY block's row-count.

Three things to track just means one extra sweep, done calmly, one block at a time.

🏆 You've got it when…

  • You always build a table with one column per value, before listing anything
  • You sweep the BIGGEST value first, block by block
  • You add up every block's count at the end — never just report the last block
