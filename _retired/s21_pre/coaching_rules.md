## Coaching-Process Review (10 Aug 2026, post-ASMOPSS-2026) — standing rules

**Root cause identified:** the on-topic/no-maintenance rule (21 Jun) keeps unit-test measurements clean, but has an unintended side effect — once a skill passes 80%+ it moves to the next topic and is *never revisited* except by accident on a milestone. Confirmed pattern across three independent skills, taught three different ways, months apart: circular arrangements (closed U43 → regressed M4 → regressed again M5), remainders (closed U34, untouched 6 weeks → failed real-exam Q10), and "Finish Line Check" (taught U44, validated U45 → never reinforced again → identical failure resurfaced on real-exam Q2/Q10/Q20). Not three content gaps — one process gap: **things that get marked resolved stop being touched.**

**Circular arrangements regressed a THIRD time at U61 (Recall Q15, 20 Sep 2026) — 6! instead of (6−1)!, same error as M4/M5.** Retired from the scored Recall rotation as of U62; see `Review_Note_CircularArrangements.md` for the full root-cause writeup (the linear-permutation rule is actively winning over the circular one on mixed papers, not passively decaying) and the offer of a widget-based 4th attempt if Lui wants to revisit it later.

**Counterintuitive finding:** on the real 2026 exam, "orange" (below-target) skills — Logic 88/90, Geometry 74/80, Applied Problems 76/80 — all performed cleanly (Q14, Q17, Q4/Q5/Q8 correct). The misses clustered in "green" (at/above-target) skills — Number Theory 89/82 (Q10 remainder), Art of Counting 87/85 (Q13, Q15, Q19). Reason: Arithmetic/Applied Problems/Logic are the *vehicle* skill inside nearly every unit's word problems, so they get free constant spiral repetition. Number Theory and Counting each got one intensive dedicated unit, hit green, then went quiet — green isn't more fragile, it's just less exercised after the fact.

**Why the Intermediate tier specifically collapsed on the real exam (18/45 = 40%, vs Basic 80%):** two of its three misses are exactly this pattern — one pure retention decay (Q10, remainder, 6 weeks untouched) and two "harder framing of an already-green skill, first time since it closed" (Q13, Q15, Counting — same pattern as M4/M5's Round 3). Intermediate tier carries the most raw marks (45/100) and is where closed skills first get re-asked in denser form — maximally exposed to both failure modes at once.

**Standing rules, effective U54 onward:**
1. **Spiral maintenance warm-up:** every unit test carries 1–2 ungraded warm-up questions (not counted against the pass bar) from a rotating list of skills untouched 4+ weeks. Queue starts: remainders, circular-repeats (both have a documented regression already).
2. **"Finish the question" is now standing, scored infrastructure, not a one-time lesson.** Every test instruction includes "before you write your answer — did you answer the EXACT question?"; grading always explicitly flags correct-method-wrong-last-step cases. U58 remains a checkpoint on whether this closed the gap — if yes, that slot converts to extra practice instead of a new lesson.
3. **Green skills get density upgrades, not just a first pass.** Once a skill (esp. Number Theory, Art of Counting) goes green, later touches (maintenance warm-ups, later units) must use denser/multi-condition real-exam-style forms, not the original teaching form.
4. **Track performance by difficulty tier (Basic/Intermediate/Applied), not just by topic, from M6 onward** — report tier breakdown every milestone so a tier-specific collapse is visible immediately rather than only surfacing on the next real exam.
- *Why:* Lui's explicit review request (10 Aug 2026) after the ASMOPSS 2026 result — see [[project-chusaki]] for the full score breakdown this analysis is based on.

## Unit Test Rules

### Format
- Always 15 questions, 3 sections of 5 questions each
- Two topics minimum per test — but BOTH topics must come from the CURRENT unit's own lessons
- Built as .docx via Node.js build script (see [[docx-template]])
- Section A: Q1–Q5 warm-up, Section B+C: Q6–Q10 medium (★), Q11–Q15 hard (★★)
- Must include: pre-scan banner, section bands, answer key on page break
- **NO-ANSWER-LEAK guard (set 26 Jun 2026 by Lui, after U33):** the WORKING RULE / pre-scan / any header band on the question pages must teach the METHOD only — NEVER print a computed value that answers (or partly answers) a question. E.g. for a factorial test, write "n! = multiply n down to 1" but NOT "3!=6, 4!=24, 5!=120…", because those are the answers to Q1–Q5. Worked numbers belong ONLY in the answer key (page break). Verify before delivery: grep the question-page body for every answer value; it must be clean.
- **3-page total fit + working space (revised 5 Jul 2026 by Lui, from U40 onward — supersedes the old forced one-section-per-page rule set 27 Jun 2026):** don't force Section A/B/C onto separate pages via page breaks anymore — let content flow naturally across the question pages. Instead, just check the TOTAL: build with **3 empty rows between each question** first, render to PDF, and confirm all 15 questions (all 3 sections combined) still fit within **3 question-pages** before the answer-key page (i.e. the whole test is still the standard 3 question-pages + 1 answer-key page, 4 pages total — it no longer matters which section lands on which page). If it fits in 3 pages, keep the 3-line spacing. **If 3-line spacing pushes the content past 3 question-pages, rebuild with 2 empty rows between each question instead** (the fallback default). Always verify the actual rendered page count before delivery — don't assume either spacing fits without checking.

### On-topic rule (set 21 Jun 2026 by Lui, after U29)
- **ALL 15 questions must test ONLY the current unit's own lesson topics.** No exceptions.
- **No maintenance / spiral / retention questions** drawn from earlier units, and **no "review" sections**.
- Cross-checking retention of prior units happens **at milestone tests only** (that is the milestone's job).
- *Why:* at U29, two off-topic "maintenance" questions (Path & Frame cost, even-count) confused Prem — he left both blank and wrote "is this the right topic?" on the paper. They risked his pass (he landed exactly 80%) and prevented a clean read of the unit's actual topic (divisibility, where he was 12/13). On-topic-only keeps each unit test a clean measurement.
- **ASMOPSS-units exception (set 23 Jun 2026 by Lui):** from **U32 onward**, the ASMOPSS-prep units may be **deliberately MIXED-topic ASMOPSS-style papers** (the real exam is fully mixed), so the on-topic rule is relaxed for them. **U31 stays on-topic** (Art of Counting — the live U30 gap). Programme is in ASMOPSS-prep mode until ASMOPSS 2026 (9 Aug 2026); see `ASMOPSS_Prep_Executive_Summary.md`.

### Pass Standards
- **Single bar for ALL tests: 80% = 12/15** *(revised 12 Jun 2026 by Lui — previously fundamental units U21–U26 required 87% = 13/15 + Sec A 5/5)*
- **Sequences formula tests:** Formula Tₙ = a+(n−1)d must appear in working. Listing/counting = 0 marks even if answer correct
- **Multi-topic consolidation tests (e.g. U26):** 4/5 minimum per section — strong section cannot mask weak section
- Section A misses still get reviewed first in analysis, but Sec A 5/5 is no longer a hard pass condition

### If Pass Standard Not Met
- No full unit repeat
- Build one targeted top-up lesson on specific gap → fresh 15-question test on same topic only
- For multi-topic tests: only failed section needs re-testing

### Rule history
The 87% fundamental-unit bar (rationale: max 2 misses ensures core method locked) was retired on 12 Jun 2026 after U25 — Lui set 80% = 12/15 as the single mastery bar for all tests. Dashboard chart reference line updated to match.

## Lesson Design Rules

### GROUND RULE — every topic is BRAND-NEW to Prem (set 24 Jun 2026 by Lui)
- **Assume ZERO prior knowledge.** Prem has NOT learned the topic at school — he is learning it from Chusaki for the very first time. Build from the absolute basics.
- **ONE new idea at a time.** Do not pile concepts. If a unit needs several moves, teach one move to automatic mastery before introducing the next (across screens or across units). "Too many concepts to remember" = the lesson failed.
- **Simple & clear, concrete-first.** Lead with concrete pictures/examples a 10-year-old relates to; introduce the rule only after the pattern is felt. Define every word. Minimal jargon.
- **Worked-example-first:** many near-identical worked examples for ONE idea before any mixing.
- *Why:* at U31 (counting) the two lessons carried ~8 moves at once (multiply, arrange, choose-2, diagonals, when-not-to-halve, repeats, squares-grid, paths). Prem was confused on the 1st (closed-book) attempt and could only pass with lessons open, saying "too many concepts." Overload, not inability. Fix = collapse to one decision + 2 core moves, defer the rest.
- **Recurred at U49 (3D Visualization, 31 Jul 2026), inside a single sub-skill this time — not just across a whole unit.** Section C (Painted Cube Puzzles) taught 4 separate near-formulas for corner/edge/face/hidden counts. Prem got the two with a clean, memorable formula right (corners=8 always; hidden=(l−2)(w−2)(h−2)) but wrote "forgot how 2 do" on all three questions needing edge or face counts, and told Lui directly: "too many solving methods to remember." Same root cause as U31, one level down — bundling several distinct special-case recipes without one unifying mental model, even within a single lesson section. **Fix for the retest re-teach:** reframe ALL FOUR counts through ONE concrete mental model — a rectangular block always has 8 corners, 12 edges (grouped into 3 sets of 4, one set per direction, each edge-cube count = that direction's size−2), 6 faces (grouped into 3 opposite pairs, each face's middle count = the other two dimensions−2 multiplied together), and 1 inside region ((l−2)(w−2)(h−2)). Same underlying maths as before, but taught as "identify which of the box's 4 physical parts (corner/edge/face/inside) a cube belongs to" — ONE classification process applied 4 times, not 4 unrelated formulas. Check this framing lands before reusing multi-formula sub-skills elsewhere.
- **U50 retest result (5 Aug 2026): the unifying-model fix did NOT land, and a second, more important problem surfaced underneath it.** U50 (the retest built specifically to fix U49's Section C) scored 8/15 (53%), with Section C actually WORSE than U49 (1/5 vs 2/5) — Prem wrote "confusing method" directly next to the Faces question, direct evidence the redesign didn't resolve his confusion with that specific formula. Take the "one unifying model" framing as *necessary but not sufficient* for this student on multi-step spatial-counting formulas — worth re-examining once exam pressure is off, rather than assuming the U49 fix note above is closed.

## Test-Taking Confidence — Answer-Overwriting (new finding, U50, 5 Aug 2026)
- **On U50, Prem correctly solved 2 questions in his working (e.g. 8+8+4=20; 12+0+0=12 — both exactly right), then crossed out his own correct answer and wrote a different, wrong one instead.** This is a distinct failure mode from "forgot how to do it" (blank/skip, seen at U49) — here the method and arithmetic were both right, and the final written answer was wrong anyway, purely from self-doubt under test conditions.
- *Why this matters:* it means some of Prem's "wrong" answers may not reflect an actual knowledge gap — always check the WORKING column, not just the final answer line, before concluding a concept isn't understood. A wrong final answer with fully correct working is a confidence problem, not a re-teach trigger.
- **Standing rule going forward:** when grading any done test, if a final answer is wrong but the working shows the fully correct method and arithmetic, flag it explicitly as a possible overwrite/self-doubt case rather than folding it into the section's "content gap" tally at face value — it changes the recommended fix (confidence-building, not a new lesson).
- **5 Aug 2026 response:** built `Confidence_Session_TrustYourFirstAnswer.html` — a short, non-scored, no-red-pen session (Lui's explicit choice over re-teaching or a 3rd retest) that has Prem redo the exact 2 overwritten questions, states one rule ("only change an answer if you find a wrong NUMBER, not a feeling"), and mixes in quick wins from already-mastered topics to rebuild trust before the 9 Aug exam. Not added to the unit-test cycle/prem_data.js scoring — it's explicitly not a scored assessment.
- **VALIDATED at Milestone M5 (6 Aug 2026, 47/100 diagnostic):** the confidence session worked. Across 25 questions on a genuinely long mixed paper, zero correct answers were crossed out and replaced with wrong ones — the exact U50 pattern did not recur. On questions he couldn't solve, Prem wrote honest "IDK"/blank instead of guessing or erasing (Q12, Q18, Q19, Q21) — a real, positive behaviour change. Q17 (painted-cube corners) was answered "ALWAYS 8" with a confident drawing, no hesitation. **Takeaway: the confidence-session format (no score, no red pen, redo-the-exact-failed-questions, one trust rule) is validated and worth reusing whenever a similar overwrite/self-doubt pattern shows up again** — don't default straight to a content re-teach when the working shows the method was already right.

### Build on proven-mastered methods first (set 9 Jul 2026 by Lui, after U40 Lesson 1 warm-up draft)
- **When a new topic (or a recap/warm-up) can be expressed through a method Prem has already mastered — proven by a unit test score of 80%+ — teach/recap it THAT way first. Don't introduce a brand-new framing or metaphor for a skill that already has a working, proven mental model.**

### Step-by-step granularity (set 21 Jun 2026 by Lui, after U30 sequences lesson)
- **One micro-step per line.** Every worked example AND every "Show Steps" reveal must show the FULL working line by line — state the rule, substitute each value, expand, group like terms, substitute the knowns, solve one operation at a time (e.g. `2a = 70 − 24` → `2a = 46` → `a = 46 ÷ 2` → `a = 23`), then a Check line. Never compress several operations onto one line.
  - **Enforced by gate from U66 v2.1 (12 Oct 2026)** after the planner itself compressed `1/4 × 2 4/5 = 1/4 × 14/5 = 14/20 = 7/10` onto one line and Prem went blank on that lesson. The planner pins every worked line + reason in a `*_worklines.json`; the gate allows at most one '=' and one operation sign per line, requires a reason, checks the arithmetic, and must catch planted bad lines. Executors copy lines verbatim and reveal them one at a time.
- **First-Step Map.** Every method lesson gives a yes/no decision tree from the story's words to the first written line (e.g. 'Is there a unit right after the fraction? → told / work it out'), on screen and as a printable card. Put away for tests.
- **Practice is not a second test.** No all-right gates or Boss rounds in practice tools; a miss shows the working and moves on; finishing unlocks the test code.
- **Independence test:** a 10-year-old must follow the working with ZERO parent help. If a step is implied, write it out. Short, compressed rows = confusing = needs supervision = rule violation.
- **Define every variable where it first appears** (e.g. "p = position (which term)"), and prefer letters that match meaning — use **p** for position, not k.
- **Re-show the governing rule/formula at the top of every screen that uses it** (e.g. a rule-band with `Tp = a + (p − 1) × d`). Don't make him scroll back to find it.
- *Why:* at U30, Prem flagged the sequences Lesson 2 as confusing on the core concept — undefined `k`, the rule not repeated where used, and working compressed into a few rows. Worked example template he wants (mirror this granularity everywhere):
  `Tp = a + (p − 1) × d` → `T2 = a + (2−1)d / T6 = a + (6−1)d` → `T2 = a + 1d / T6 = a + 5d` → `(a+1d)+(a+5d)=70` → `(a+a)+(1d+5d)=70` → `2a+6d=70` → `2a+(6×4)=70` → `2a+24=70` → `2a=70−24` → `2a=46` → `a=46÷2` → `a=23` → check.

### Algebraic-rearrangement depth standard (set 3 Sep 2026 by Lui, after U60 Lesson 2's 1st attempt)

- **Lui's own worked breakdown is now the required depth template for ANY algebraic-rearrangement teaching** (isolating a variable, solving for an unknown, "move it to the other side"), not just this one lesson:
  1. Derive the working formula via fraction form first: `Area = ½ × b × h` → `Area = ½ × b/1 × h/1` → `Area = (1×b×h)/(2×1×1)` → `Area = bh/2`.
  2. Step 1 — isolate by moving the denominator across: `2 × Area = bh` — explicitly state the general logic being used ("move 2 from the right side to the left side, divide becomes multiply — same logic as switching sides and flipping + to − or − to +"), not just the result.
  3. Step 2 — rephrase the isolated equation as "finding b" or "finding h": `bh = 2 × Area`.
  4. Step 2a / 2b — solve each variant explicitly, each with its own stated logic: `b = (2×Area)/h` ("move h from left to right, multiply becomes divide"); `h = (2×Area)/b` ("move b from left to right, multiply becomes divide").

Never jump straight from the original formula to the rearranged answer form in one or two lines, even if the arithmetic itself is simple.
